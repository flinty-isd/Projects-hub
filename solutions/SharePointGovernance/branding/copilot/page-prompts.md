```
## What this site is for
SharePoint Online is governed as a business-as-usual service. The controls in the SharePoint Migration PID v4.2 are enforced by Power Automate flows that run on the lists on this site. You ask for something by adding an item to a list; the flow checks it, asks the right approvers and records the decision.

## Start here

- I need to… | Do this
- Get access to a site | Raise an access request. See Request access for what is allowed.
- Get a new site | Raise a site request. See Request a site.
- Review who can use my site | Answer the review email. See Access reviews.
- Decide on a file share | See File shares.

## The controls

- Flow | Runs | Control it enforces
- 01 Access request | New Access Requests item | The Access Method Decision Table: service and shared accounts prohibited, staff without a Microsoft licence use the Base8 CMS in the Employee App, licence and Entra ID P2 checks, guests time-bound to 90 days, PIM for admins, group-based grants
- 02 Guest access expiry | Daily 06:00 | Contractor guest access is time-bound and reviewed; the site owner decides removal unless the Board makes it automatic
- 03 Site provisioning | New Site Requests item | Naming standard, two named owners, permission groups, external sharing off by default
- 05 File share disposition | New File Share Register item | File shares move to SharePoint case by case only; system-dependent shares are excluded
- 06 Access recertification | Monthly, 1st, 07:00 | 90-day review of site access, orphaned-site detection, quarterly review of privileged admin roles
Flow 04 (InfoPath triage) was retired on 25 October 2026. InfoPath forms are now triaged with the PID v4.2 Criticality Decision Tree through the programme's Flow 8.

## Reading a status
Every Status column shows its value in a coloured box. The words always say what happened; the colour is a quick guide.

- Colour | Means | For example
- Green | Granted, approved or ready | Granted; Provisioned; Ready for migration
- Red | Blocked, rejected, returned or failed: something needs fixing or was refused | Blocked - Licence required; Returned - Naming standard; Orphaned - owner inactive
- Blue | Closed with guidance, or a follow-up step | Closed - Use Employee App; Kept - owner decision; Read-only
- Grey | Not decided yet | Submitted; Removal pending owner decision; Awaiting owner decision
```

```
## How to ask
Add an item to Access Requests: pick the site, your user type and a business justification. Flow 01 checks the request against the Access Method Decision Table and sends it to the approvers below. Access is always given through a security group, never to one person directly.

## Access Method Decision Table

- User type | What happens | Approved by
- Employee - view only (no Microsoft licence) | Closed: use the Base8 CMS in the Employee App | No approval
- Employee - edit / collaborate | Needs an M365 licence that includes SharePoint (F3 or above), else Blocked - Licence required | Site primary owner
- Site Owner / Author | Needs a SharePoint licence (E3 or equivalent) and Entra ID P2, else Blocked | Line manager and SharePoint service owner
- Long-term contractor | Guest access with an end date within 90 days, else Rejected - Not time-bound | Site owner and InfoSec
- Screen / kiosk / display | Closed: use the published display page | No approval
- Privileged admin | IT Operations creates a PIM eligible assignment | InfoSec
- Service / shared account | Rejected - Prohibited | Not allowed

## After approval

- If the site's group is synced from on-premises AD, the Service Desk adds you to the AD group (status: Approved - awaiting AD group change).
- Otherwise you are added to the Entra group straight away (status: Granted).
- Contractor guests: the sponsor and site owner get one reminder 14 days before the end date. Renewing means a new access request, for 90 days at most. See Access reviews for what happens on the end date.
```

```
## Before you ask

- A URL alias in lower case that follows the naming standard [org]-[location]-[department]-[site], with a known location code. Otherwise the request is Returned - Naming standard.
- Two different, enabled, internal people as primary and secondary owner. Otherwise it is Returned - Ownership invalid.
- An Owners group and a Members group (Entra object IDs). Visitors and Guests groups are optional.
- A sensitivity: General, Confidential or Highly Confidential.
- Whether you need external sharing. It is off unless approved.
Then add an item to Site Requests.

## Who approves

- The SharePoint service owner approves every new site.
- InfoSec also approves when you ask for external sharing or the site is Highly Confidential.

## What you get
Once the site is created, IT Operations applies and registers its Sites.Selected grant, then the baseline is applied: permissions through groups only, your secondary owner as a site admin, external sharing off unless approved, no custom script and your sensitivity label. Without the grant the request shows Provisioning failed and the service owner is told. The site is added to the Site Register with its first access review due in 90 days, and both owners are told.
```

```
## 90-day access review
On the 1st of each month, flow 06 emails the primary owner of every site whose review is due, listing its Owners and Members groups. Confirm the list is right, or say who should be removed. Removals go to the Service Desk. Every answer is logged and the next review is set for 90 days later.

## Orphaned sites
If a site's primary owner account is no longer enabled, the site is marked Orphaned - owner inactive. The SharePoint service owner and IT Operations promote the secondary owner and name a new one.

## Guest end dates
Guest access is recorded in the Guest Access Register. On the end date, the site owner or sponsor is asked to confirm removal:

- Confirmed: the guest is removed from the site's Guests group and marked Expired - access removed; the sponsor, owner and InfoSec are told.
- Not confirmed: access stays, the guest is marked Kept - owner decision and InfoSec is told. Continuing access needs a new access request.
If the Control Board rules expired guest access a critical class, removal on the end date becomes automatic.

## Admin roles
In January, April, July and October, InfoSec confirms the SharePoint Admin role is PIM-eligible only.
```

```
## How a file share is decided
File shares move to SharePoint case by case. Each share in the File Share Register is checked in this order:

- An integration marker, app back-end or generic account: Excluded - system dependent. IT Operations agrees whether to remediate, archive, delete or move it to a non-SharePoint platform.
- Unmodified for 3 years or more: the owner is asked to approve archiving.
- Otherwise the owner and the SharePoint service owner approve migration. Shares with High permission complexity have their permissions remediated first.
```

```
## Roles
The flows send approvals to roles, not named people, so a change of staff only changes a setting.

- Role | Approves or receives
- SharePoint service owner | Approves new sites and file share migrations; second approver for Site Owner / Author access; receives provisioning failures and orphaned-site alerts
- Security and Architecture (InfoSec) | Approves guest access, privileged admin roles, and sites with external sharing or Highly Confidential content; quarterly admin-role review
- IT Operations owner | Applies and registers the Sites.Selected grant for each new site; creates PIM assignments; agrees dispositions for excluded file shares and permission remediation; orphaned-site alerts
- Service Desk | Fulfilment tickets: AD group changes and access removals
```
